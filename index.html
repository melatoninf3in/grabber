Overview

Discord Quests are tracked client-side. The browser holds the session state the client uses to report quest progress. QuestPilot reads that state from the tab you are already logged into, asks Discord's own API for the account context, and reports completion. Nothing is uploaded except the confirmation summary.

How it works

Discord's client is a single-page application. Quest progress, like most client state, lives in the browser storage layer and syncs through Discord's own API. That design keeps the interface responsive, and it means the same session that renders the quest panel can drive quest completion programmatically. QuestPilot is a thin wrapper over that session. It does not bypass authentication because it does not need to — it uses the session already present in your tab.

This is the same pattern behind most browser automation: the browser is authenticated, so a small script running in the page inherits that authentication. The distinction that matters is between tools operating on your own session and tools trying to obtain someone else's. QuestPilot only touches the tab it runs in, and it is removed by deleting the bookmark.
